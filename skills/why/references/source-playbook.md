# Evidence categories and playbooks

The why skill spawns one investigator per category that has a connection. Each reads exactly one playbook from `sources/`. **Re-run `tools.search` at the start of every investigation; the live Executor catalog wins over the paths written here** (catalogued 2026-08-23).

| Category | What it physically holds | The "why" only it surfaces | Playbook | Executor connection here |
|---|---|---|---|---|
| Source control history | git history, `gh` PRs, code comments, tests | implementation-time rationale captured in review: PR problem statements, review debates, inline constraints, test names encoding edge cases, commit ↔ ticket links. Most trustworthy — tied to the diff that shipped. Always spawn. | [`code-archaeology.md`](./sources/code-archaeology.md) | git, `gh`; `github.org.githubPullRequestsOauth.search_pull_requests` / `pull_request_read` when `gh` lacks access |
| Issue / ticket tracker | tickets, epics, status updates, attachments | the product/business forcing function: customer asks, compliance deadlines, parent-initiative framing, scope changes, labels (`customer:*`, `incident-followup`, `perf-regression`) | [`jira.md`](./sources/jira.md) | `mongodb_devprod_mcp.org.localmongodbdevprodmcp.jira_search_issues` (JQL) |
| Long-form documents | PRDs, specs, RFCs, design docs, ADRs, postmortems, meeting notes | written-out design rationale: problem statements, "alternatives considered / rejected", strategy priorities, postmortem action items tied to code | [`confluence.md`](./sources/confluence.md) | `...confluence_search` (CQL), `...confluence_get_page`; Glean for Google Docs |
| Real-time team chat | Slack threads, incident channels, PR URL mentions | deliberation that never reached a doc: incident fire-drills, author↔reviewer Q&A, "we decided X because Y", rationale for small changes | [`glean.md`](./sources/glean.md) | `glean-data.user.default.search` (indexes Slack, Docs, Jira); no direct Slack connection |
| Infrastructure observability | metrics, dashboards, alerts, logs | runtime reality that motivated the code: alert thresholds matching code constants, spikes before a merge, dashboards created as action items | [`grafana.md`](./sources/grafana.md) | `grafana.org.default.*` — see the `observability-mcp-tools` skill |
| Error / log evidence | indexed service logs, build-failure groups | the specific errors and trajectories behind defensive code: error strings through the target, first/last-seen windows bracketing the ship date, an error stopping at a version | [`splunk.md`](./sources/splunk.md) | `splunk.org.default.splunk_run_oneshot_query`; `...bb_search_bfgs` (Build Failure Groups) |
| Incident record (cross-cutting) | incidents, notes, alerts, change events | formal incident timelines that reference the target; postmortem links | [`pagerduty.md`](./sources/pagerduty.md) | `pagerduty.user.default.list_incidents`, incident notes/alerts/change events |
| CI history | task history, versions, BFGs | flake vs regression, when a test started failing, the patch that "fixed" it | [`evergreen.md`](./sources/evergreen.md) | `...evg_get_task_history`, `...evg_get_version`, `...bb_search_bfgs` |
| Product analytics warehouse | usage, experiment/flag exposure, billing events | where a threshold constant came from (p99 of a column), flag-gated ship decisions, migration scale | none | no connection in this environment — report as a gap in Sources Consulted |

Cross-cutting: [`incident-postmortem.md`](./sources/incident-postmortem.md) — add to every investigator when the target looks defensive (null checks, retry, timeout, rate limit, feature flag, egress guard, OOM handler).

A connection that fits more than one category goes under its primary evidence (Glean: chat, noting it also indexes docs and tickets).
