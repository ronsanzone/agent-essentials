2  ·  DATA MOVEMENT AND DURABILITY

2.1

A DOCUMENT IS IN ONE COLLECTION AT EVERY COMMIT.

The agent moves documents in sub-batches. Each sub-batch finds, inserts and deletes its documents inside one transaction committed with w:majority. No checkpoint is kept; each run asks again for what is still old and still in the source (figure 2-1).

CAUTION

Do not drop or rename the target of an ACTIVE policy. Preflight runs once per run; a later insert can create an ordinary hot collection and keep filling it.

2.2

EACH RUN LOOPS UNTIL NOTHING OLD IS LEFT.

Each run first checks that both namespaces are allowed, exist and are plain collections, and that the date field can be aged. Discovery reads only _id values at or past the cutoff, oldest first, and stops at maxDocumentsPerRun (table 2-1). Chunks of 1,000 ids feed the workers; each worker loops sub-batch transactions until a re-find returns nothing (figure 2-2).

2.2.1

Exactly-Once Placement.

A sub-batch commits only when the insert count and the delete count both equal the re-found count; otherwise it aborts and its documents stay in the source. A duplicate _id aborts only its own sub-batch.

VERIFY A RUN

  1. 1RUN DOC - read lastNRuns
  2. √ state - SUCCESS
  3. 2documentsFailed - read
  4. √ documentsFailed - 0
  5. 3TARGET - countDocuments
  6. √ delta = documentsMoved
  7. 4POLICY errorMessage - empty
